# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BikeSpeed is a fullscreen iPhone bike speedometer: an 80s-car-style analog gauge showing live GPS speed, plus average/max speed, distance, duration, altitude, climb and live gradient, GPS position, and direction of travel, with Start/Pause/Reset trip controls (and auto-pause) and a Settings screen for max gauge speed, metric/imperial units and the auto-pause toggle. Trips record in the background, capture a route track and height profile, and are saved to a trip log with a map, a GPX export, and lifetime/personal-best aggregates. Portrait only, home indicator hidden, screen-sleep disabled — designed to run mounted on a bike handlebar. The **status bar stays visible** (`persistentSystemOverlays(.hidden)` in `ContentView` hides only the home indicator, and nothing sets `UIStatusBarHidden`): a rider wants the clock and battery, so this is deliberate, not an oversight to "fix".

Localized in English and Norwegian (`nb`) via String Catalogs, following device language.

## Commands

Build from the command line (targets the iOS Simulator; the project has no macOS destination):
```
xcodebuild -project BikeSpeed.xcodeproj -scheme BikeSpeed -destination 'platform=iOS Simulator,name=iPhone 17' -configuration Debug build
```

Run the unit tests (Swift Testing; the `BikeSpeedTests` target, driven by the shared `BikeSpeed` scheme):
```
xcodebuild test -project BikeSpeed.xcodeproj -scheme BikeSpeed -destination 'platform=iOS Simulator,name=iPhone 17'
```
Tests mirror the production folder layout (`Services/TripManager.swift` → `BikeSpeedTests/Services/TripManagerTests.swift`) and are behaviour-level: they drive `TripManager` by feeding fixes into `LocationManager.acceptedLocations` through `TripTestHarness` (`BikeSpeedTests/Fixtures/`), whose `move(meters:seconds:)` reads as riding rather than as CoreLocation. Two things will otherwise look like app bugs when they're really the guards working:
- `move(meters:)` must imply a speed under 120 km/h (33.3 m/s) or `TripManager`'s teleport guard discards the fix and no distance accrues — `move(meters: 50)` at the default one second is 180 km/h.
- Time is injected (`TripManager(now:)`), so tests advance `TestClock` and call `tripManager.tick()` rather than sleeping. Never add a `sleep` to make a timing test pass. This is also why `TripDataStack.delete` is `async` — so a test can *await* the sync notification instead of sleeping to see whether it arrived.

Storage tests use an in-memory `ModelContainer` (`makeStack()` in `BikeSpeedTests/Fixtures/StoreFixtures.swift`), which is what makes the suite parallel-safe with no temp directories at all.

For iteration, prefer opening `BikeSpeed.xcodeproj` in Xcode and using Run/Preview.

To manually run in the simulator:
```
xcrun simctl boot "iPhone 17"   # if not already booted
xcrun simctl install booted <path-to>/BikeSpeed.app
xcrun simctl launch booted lekanger.BikeSpeed
```
Location permission can be pre-granted for testing with `xcrun simctl privacy booted grant location lekanger.BikeSpeed`, though this simulator/iOS version has been observed to still show the system prompt on each fresh launch regardless — not an app bug, just re-verify on a real device if in doubt.

To exercise speed/course/altitude without a real ride, use Xcode's Debug ▸ Simulate Location, or simulate a route from the command line:
```
xcrun simctl location booted start --speed=8 --interval=1 59.9139,10.7522 59.9184,10.7522
```
`--speed` is **m/s**, not km/h (8 m/s ≈ 29 km/h). Three things to know, each of which will otherwise look like an app bug:
- The process must outlive the shell that launched it, or fixes silently stop arriving and the app appears frozen (needle stuck, distance stuck at 0).
- `simctl location booted set <lat,lon>` is not a substitute for a route: a static point reports `CLLocation.speed` as the negative "unknown" sentinel, which `TripManager` deliberately ignores. To simulate a **standstill** (e.g. to trigger auto-pause) run a slow route instead — `--speed=0.2` between two points a few metres apart — which produces real near-zero speeds.
- Don't jump the position between routes while a trip is running. A multi-kilometre teleport is exactly what `TripManager`'s teleport guard is built to reject, so distance will legitimately refuse to count it. Start the route before tapping Start, and keep successive routes adjacent.

## Architecture

Model layer speaks pure SI units (meters, m/s, degrees, seconds) throughout; only the view layer converts to km/h-vs-mph via `Measurement<UnitSpeed>`/`Measurement<UnitLength>`, which also localizes unit abbreviations for free (e.g. "km/t" in Norwegian).

State is `@Observable` throughout (`@State` to own, `@Environment`/`@Bindable` to pass) — no `ObservableObject`/`@Published` anywhere. The one Combine holdout is `LocationManager.acceptedLocations`, and deliberately: an accepted GPS fix is an *event*, and Observation observes *state*.

- **`Models/`** — `TripState` (idle/running/paused), `MeasurementSystem` (metric/imperial + conversion/formatting helpers), `CompassDirection` (8-point compass derived from a GPS course angle), `GPSSignalQuality` (good/fair/poor bands), plus the trip-log types below. Also the pure value types that hold the subtle sensor logic so it can be unit-tested without CoreLocation/CoreMotion — **read these before touching the numbers**: `ElevationAccumulator` (deadband summing of ascent/descent), `GradeCalculator` (sliding-window rise/run), `CircularMean` (unit-vector EMA for a compass bearing, so smoothing 359°→1° doesn't sweep through south), `RouteSample`/`AltitudeSample` (the per-trip track and height-profile points), and `CLLocation+UsableAltitude` (the single altitude-trust rule every consumer shares).
- **`Services/LocationManager.swift`** — wraps `CLLocationManager`/`CLLocationManagerDelegate`, publishing filtered speed, course, altitude, coordinate, and magnetometer `heading`. Fixes are filtered on two independent axes (see the constants at the top of the file): *accuracy* — speed/course/altitude are rejected or held at their last valid value rather than accepted as noise — and *age*, since `startUpdatingLocation()` replays the last cached fix, which can be minutes old yet perfectly accurate. Everything downstream treats an emitted fix's `timestamp` as "now", so both filters have to hold. `course` is deliberately sticky below a speed floor (GPS course is noise at a standstill), so `travelDirection` hands over to the smoothed `heading` there and back to course once moving — `isCourseLive` is the flag that makes that switch possible, since sticky `course` is never nil once set. Emits accepted fixes via a `PassthroughSubject` for `TripManager` and `AddressLookupManager` to consume — it does not itself gate on trip state, so the gauge/compass/position stay live even when idle. Conforms to `LocationSource` (`setBackgroundUpdates(_:)`, the seam `TripManager` toggles for background recording).
- **`Services/TripManager.swift`** — owns the Start/Pause/Reset state machine and accumulates distance/average-speed, plus ascent/descent/gradient and the route track and height profile, from `LocationManager`'s accepted fixes. Every accumulation hangs off the single `consume(_:)` funnel, so it inherits the running/auto-pause gating, GPS-teleport guard (with a 3-strike re-anchor so one bad anchor can't freeze distance for the rest of the ride) and jitter floor for free. Elapsed active time is wall-clock based (correct across backgrounding) and driven by an injected clock (`now:`) plus a `tick()` the timer calls — so tests advance time deterministically instead of sleeping. Auto-pause (`isAutoPaused`) freezes distance *and* the clock while the rider is stopped — the clock is the point, since average speed is distance ÷ active time and would otherwise sag at every red light. It's a flag on `.running` rather than a `TripState` case so a manual pause stays distinguishable (an auto-pause must not survive as one, and `canSaveTrip` must not light up mid-ride); the pause/resume thresholds are deliberately different (hysteresis) because GPS speed drifts at a standstill. Elevation is *sampled* from the injected `AltitudeSource` (barometer, GPS fallback — latched once per trip) at each accepted fix, never on its own subscription, so climb inherits the same gating and doesn't accrue phantom metres at a standstill. Calls `LocationSource.setBackgroundUpdates(_:)` on start/resume vs pause/reset so GPS stays awake only while recording.
- **`Services/AddressLookupManager.swift`** — reverse-geocodes `LocationManager`'s accepted fixes into the street name shown on the direction cell's caption line. Subscribes to the same `PassthroughSubject` as `TripManager` and, like it, doesn't gate on trip state. Lookups are gated on distance moved *and* time since the last attempt, with exponential backoff on failure, because reverse geocoding is a network call and `CLGeocoder` throttles callers that ask too often — see the file before touching those constants. Uses `MKReverseGeocodingRequest` on iOS 26+ and `CLGeocoder` below; the two return different granularity, so the modern path trims the formatted address down to a bare street.
- **`Services/SettingsStore.swift`** — persists `maxGaugeSpeedKMH` (always canonical km/h regardless of display unit), `measurementSystem`, `appLanguage` and `autoPauseEnabled` to `UserDefaults` directly (not `@AppStorage`, which is unreliable outside a `View`; the `didSet` on each property *is* the persistence, and `SettingsStoreTests.settingsSurviveARelaunch` is what pins that the `@Observable` macro keeps those observers firing).

### Trip storage (SwiftData)

Saved trips live in **SwiftData**, not JSON — `TripLog.json` and `Routes/<uuid>.json` were migrated away and their code deleted. Trips **mirror to the user's private iCloud (CloudKit) database automatically** — no toggle — via `cloudKitDatabase: .private(...)` in `TripModelContainer.app()` plus `BikeSpeed.entitlements` (the project's only entitlements file, at the repo root beside `Info.plist` for the same reason: outside the synchronized `BikeSpeed/` folder so it isn't copied as a resource). The container id lives once in Swift (`TripModelContainer.cloudKitContainerID`) with a hand-kept twin in the entitlements plist. A *non*-CloudKit (REST/web-service) backend is still future work and is what the `TripSyncEngine` seam and the dormant sync metadata are for — do not conflate the two. **Read `Models/StoredTrip.swift` before changing anything here.**

  **Known limitation (documented, not yet fixed):** with sync on, a user who ran the *legacy* app on two devices — each still holding `TripLog.json` — and upgrades both can get duplicated trips, because each device's `LegacyTripLogImporter` imports locally (the dedup in `TripRepository.insert` is a *local* `existingIDs()` check) before CloudKit merges the other device's rows. CloudKit dedupes on its own `CKRecord.ID`, not on `id`, so it can't collapse them. The planned fix is an `id`-keyed dedup pass after import/merge (keep one row per trip `id`); it's a CloudKit-side app concern, still separate from the REST seam.

- **`Models/StoredTrip.swift`** — the `@Model`. Deliberately a different type from `TripLogEntry`: the entry is the domain *value* (a `Codable` struct — what `TripLogSummary` reduces, what the list draws, what a REST backend would put on the wire), and this is the *row*. Every constraint on it is a **CloudKit** constraint, not a SwiftData one: no `@Attribute(.unique)`, every attribute defaulted, no relationships. `StoredTripTests.theSchemaIsCloudKitCompatible` fails the build if that is broken — it really does validate (a hostile schema throws at container build, entitlement or not). Carries sync metadata the *REST* backend will read (`updatedAt`, `deletedAt`, `syncedAt`, `remoteID`) but which CloudKit mirroring does not — it stays dormant so enabling that later backend never needs a schema change.
- **Tracks and height profiles are `Data` blobs** (`@Attribute(.externalStorage)`), not child models. A 40 km ride is thousands of samples; as a to-many relationship that is thousands of CKRecords for one trip, against CloudKit's 400-per-operation cap. As a blob it is one CKRecord + one CKAsset — and Core Data faults it in only on property access, so the trip list never pays for a track it does not draw. **Do not fold either payload back into `TripLogEntry`**, and do not read `routeData`/`altitudeData` from a list row.
- **`Services/TripDataStack.swift`** — the one environment object: owns the container, the repository, and the sync seam. Save and delete go through the **main context** on purpose, so the two paths a user is actively watching never depend on a background context's save propagating.
- **`Services/TripRepository.swift`** — a `@ModelActor`, deliberately narrow: only the payload read (for the detail view) and the bulk import. `@Model` types are not `Sendable` and never cross the boundary — only `Data`/`UUID`/value types do.
- **`Services/TripSyncEngine.swift`** — protocol + `NoOpTripSyncEngine`. Not for iCloud (that's the `ModelConfiguration` flag now live in `TripModelContainer`), but for a *non*-CloudKit backend. Every mutation in `TripDataStack` already announces itself to it, and `TripDataStackTests` fails if a new mutation path forgets to.
- **`Services/LegacyTripLogImporter.swift`** — the one-shot JSON import, run from `BikeSpeedApp`'s `.task`. Idempotency is *state, not a flag*: it runs while `TripLog.json` exists, and only a verified import deletes it. **A log that will not decode is never deleted** — the old store swallowed a decode failure into `[]` and then persisted that over the user's history, and this is the guard against inheriting it (`anUnreadableLogIsNotDeleted`). Its private `LegacyTripLogEntry` is frozen: it describes what v1.1 wrote, so it must not be refactored to follow `TripLogEntry`.
- `SWIFT_APPROACHABLE_CONCURRENCY = YES` means a `nonisolated async` func runs on its **caller's** executor. `TripLogDetailView`'s `Task.detached` is load-bearing: "modernising" it into a bare `await` silently moves the O(samples) decode and GPX render back onto the run loop, with no compiler warning and no failing test.
- **`Views/`** — `GaugeFaceView` (Canvas: dial/ticks/danger-arc, redrawn only when max speed changes) + `NeedleView` (a `Shape`, rotated every update) compose into `SpeedometerGaugeView`. The gauge sweeps 270° from -135° to +135° (12 o'clock = 0 speed midpoint convention documented inline); see `GaugeFaceView`'s angle-to-point math if adjusting tick layout. `StatsPanel` is the 2×2 grid of `StatCell`s under the gauge (fed by the `TripStats`/`LocationReadout` value structs, not loose args); each cell holds N readouts paged by tap or horizontal swipe via `StatCell.Paging` — **the page count and dots derive from `names.count`, so a new readout is an extra page, not a wider grid**. The direction cell rotates its arrow icon directly by the course angle (SwiftUI's rotation convention already matches course's clockwise-from-north convention, no axis flip needed) — there is no separate `DirectionIndicatorView`. `TripLogListView` is a `@Query` list with a `TripLogSummarySection` (lifetime totals + personal bests) on top; `TripLogDetailView` lazily loads the trip's payload blobs in a `Task.detached` and renders a `Map` route polyline, a height-profile `Chart`, and a `ShareLink` GPX export (`GPXExporter`).
- **`BikeSpeedApp.swift`** constructs `LocationManager` and `SettingsStore` first, then `TripManager(locationManager:altimeter:settings:)` and `AddressLookupManager(locationManager:)` (order matters — both depend on location, and `TripManager` also needs settings for the auto-pause toggle), plus the `TripDataStack`, and injects them all via `.environment`. `AltimeterManager` is the exception: it is not observable and not in the environment, because no view reads a barometer. The same container is injected twice — as the `TripDataStack` and via `.modelContainer` — and must stay the same one, or `@Query` would read a different store than the saves land in.

### Xcode project notes

- Targets iOS only (`SDKROOT = iphoneos`, `IPHONEOS_DEPLOYMENT_TARGET = 18.0`, `TARGETED_DEVICE_FAMILY = 1`). The floor is 18 rather than 17 for SwiftData: `#Index`, `propertiesToFetch`, and History tracking (the primitive a future cloud sync reads to know what changed locally) are all iOS 18. It was originally generated as a macOS app template and was retargeted by hand-editing `project.pbxproj` (no Xcode GUI in this environment) — if something looks like a leftover macOS setting, it's likely just not cleaned up yet.
- `GENERATE_INFOPLIST_FILE = YES` — usage-description and other Info.plist keys live as `INFOPLIST_KEY_*` build settings in `project.pbxproj` (`NSLocationWhenInUseUsageDescription`, `NSMotionUsageDescription` for the barometer, etc.), plus `InfoPlist.xcstrings` for the localized location usage description. Only a curated set of keys has an `INFOPLIST_KEY_*` mapping — an unmapped one is accepted and then silently ignored, so verify a new key in the built product's `Info.plist`. That's exactly why `UIBackgroundModes = location` (which enables background trip recording) lives instead in the partial `Info.plist` at the repo root (`INFOPLIST_FILE = Info.plist`, merged with the generated keys); it sits outside `BikeSpeed/` deliberately — inside the synchronized folder it would also be copied as a resource and the build fails with two Info.plists.
- Uses a `PBXFileSystemSynchronizedRootGroup` — new files dropped into `BikeSpeed/` are picked up automatically, no manual pbxproj edits needed for new Swift files (this applies to `.xcstrings` files too).
- `Localizable.xcstrings` holds all UI-facing strings (en + nb), keyed by the English source string. Compass abbreviations are localized too (Norwegian swaps the east/west axis: Ø/V for E/W), keyed as "N"/"NE"/… — note these single-letter keys mean a bare `Text("N")` anywhere would now get translated.
- Strings that are resolved to a `String` in code (rather than handed to SwiftUI as a `LocalizedStringKey`) must go through `AppLanguage.localizedString(forKey:)`, not `String(localized:)` — the latter ignores the in-app Language override and follows the device language instead. See `AppLanguage` for why.

Bundle identifier: `lekanger.BikeSpeed`. Swift 5.0, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`.
